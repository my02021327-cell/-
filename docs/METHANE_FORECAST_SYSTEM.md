## 1. 자료 — 무엇을 쓰고 무엇을 버렸나

정본은 `data/master_bgp_2018_2023.csv` **2,086일 × 61열** (2018-01-01 ~ 2023-09-17).
저장소의 옛 `data/master.xlsx` 는 A/B 계열을 평균 낸 축약본이라 쓰지 않는다.

### 1.1 타깃 결측의 구조 — 이것이 설계 전체를 결정한다

```
CH4_m3d = biogas_AB_m3d × CH4_pct / 100

biogas_AB_m3d   결측  0.0 %     ← 유량계는 매일 기록된다
CH4_pct         결측 39.4 %     ← 가스분석을 매일 하지 않는다
CH4_m3d         결측 39.4 %     ← 위 둘의 곱이므로 농도 결측이 그대로 전이된다
```

타깃 결측 821일은 **전부 농도 미측정일**이다. 「메탄 데이터가 없다」가 아니라
「농도만 없다」는 뜻이고, 그래서 두 가지가 가능해진다.

1. **유량은 완전 관측 계열**이므로 시계열 모델에 그대로 쓸 수 있다(라벨 2,086일).
2. **농도만 보간**하면 된다. 39.4 % 를 통째로 회귀로 만들어내는 것보다 자유도가 훨씬 작다.

### 1.2 품질 규칙 (`src/bgp/config.py` · `data.apply_dq`)

| 규칙 | 처리 |
|---|---|
| 물리 범위 밖 값 | 결측 처리 (pH 6~9, CH₄ 30~80 %, 온도 20~45 ℃ …) |
| 2023년 `ALK_B` (VFA_B 로 오염) | `ALK_B_mgL`·`VFA_ALK_B` 를 결측 처리. **A 계열만 사용** |
| 온도 센서 고장 플래그 구간 | 해당 온도를 결측 처리 |
| 열역학 검사 `0 < Y_COD ≤ 0.35` | 위반 플래그. 연도별 위반율을 항상 보고 |

측정된 열역학 위반율 — **2018년 72.0 %**, 2019 12.6, 2020 12.1, **2021 0.9**, 2022 13.2,
2023 27.8 %. 2018년은 COD 계측 신뢰성이 낮아 Y_COD 기준선 산출에서 제외해야 한다.

## 2. 결측 보간 — 논문 근거와, 그 논문을 그대로 쓰면 안 되는 이유

### 2.1 논문이 말하는 것

Meola & Weinrich (2025) §2.3 Algorithm 1 은 결측을 「같은 시점의 다른 관측으로 학습한
모델」로 대치하고, 개별 알고리즘이 유효하지 않은 출력을 내면 다음 모델로 넘어간다.
후보는 **BayesianRidge → AdaBoost → GradientBoosting** 이다.
그리고 논문은 결측 처리 방식을 고정하지 않고 **최적화 대상 데이터준비 파라미터**로 둔다
(Sobol 분석에서 세 데이터셋 모두 NaN handling 이 상위 기여 인자였다).

### 2.2 그대로 적용하면 오차가 3배가 된다

관측값을 일부러 가리고 복원하는 **가림 실험**으로 후보를 실제로 재봤다
(`impute.masking_validation`, 간격당 80블록).

| 간격 | 소프트센서(논문) | ffill | 선형보간 | 선택 |
|:---:|---:|---:|---:|:---:|
| 1일 | 1.503 %p | 0.734 | **0.370** | 선형 |
| 2일 | 1.511 | 0.432 | **0.468** | — |
| 3일 | 1.451 | **0.539** | 0.581 | — |
| 5일 | 1.300 | 0.735 | **0.586** | 선형 |
| 7일 | 1.376 | 0.827 | **0.673** | 선형 |
| **가중 평균** | **1.510** | 0.768 | **0.536** | **선형** |

소프트센서가 **가장 나쁘다.** 이유는 명확하다 — CH₄ 농도는 시간적으로 매우 매끄럽고
(ACF(1) = 0.968, 일간 변화 SD 0.86 %p) 동시점 설명변수는 약하다. 시간 이웃 정보를
소프트센서에 넣으면(`soft_neigh`) 0.640 %p 로 회복되지만 여전히 선형보간에 진다.

### 2.3 그래서 채택한 것 — 「방식 선택」을 논문 방식대로

`HybridImputer` 는 논문의 **취지**(NaN 처리는 최적화 대상이다)를 따르되, 후보를
{linear, ffill, softsensor, soft_neigh} 로 넓히고 **폴드 학습셋 안에서** 가림 실험으로 고른다.

- 배치 재구성(과거 복원) → **linear** 채택, MAE **0.536 %p** ≈ 메탄 ±55 ㎥/d
- 실시간 경로(`causal_only=True`) → **ffill** 채택, MAE **0.768 %p**

### 2.4 보간 라벨의 사용 규약 — 이걸 어기면 성능이 가짜가 된다

- 보간으로 만든 라벨은 **학습에만** 쓴다 (1,265 → 2,086일, +65 %).
- 평가는 **실측 라벨에서만** 한다. 보간 라벨로 평가하면 「보간 모델을 얼마나 잘
  흉내 내는가」를 재게 된다.
- 코드에서 `label_is_observed` 플래그로 구분하고, `run_band` 의 시험 표본은
  `obs_all` 이 참인 쌍만 쓴다.

## 4. 지평 구간별 모델 (요구사항의 핵심)

### 4.1 왜 구간을 나누는가

같은 자료에서 persistence 성능이 지평에 따라 완전히 갈린다(2022년 이후 평가).

| 지평 | 1일 | 2일 | 3일 | 5일 | 7일 | 14일 | 30일 | 60일 | 90일 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| persistence R² | 0.934 | 0.857 | 0.787 | 0.663 | 0.514 | 0.234 | −0.612 | −1.820 | −2.624 |

**h ≤ 3일에서는 전일값이 이미 거의 전부를 설명하고, h ≥ 30일에서는 아무것도 설명하지
못한다.** 하나의 모델로 두 체제를 동시에 최적화할 이유가 없다. 그래서 요구하신 대로
**1–3 / 3–5 / 5–7 / 7–14 / 14–30 / 30–60 / 60–90일** 일곱 구간을 각각 독립으로 적합·선택·평가한다.

### 4.2 직접 다단계 (direct multi-step)

구간 (lo, hi) 안에서 원점 t 의 피처에 **지평 h 를 피처로 추가**해 y(t+h) 를 직접 맞힌다.
재귀 예측처럼 오차가 누적되지 않고, 구간 안의 여러 지평이 표본을 공유한다.

### 4.3 두 가지 표적형 — 수준과 잔차

트리 계열은 수준을 외삽하지 못하므로, 같은 정보를 **원점 실측 대비 변화량**으로 주면
크게 유리해진다.

```
level :  모델이  y(t+h)              를 직접 맞힌다
delta :  모델이  y(t+h) − anchor(t)  를 맞히고, 예측 시 anchor 를 되더한다
         anchor(t) = 원점까지의 마지막 실측 메탄 (= naive 의 정의와 동일)
```

`delta ≡ 0` 이면 정확히 naive 가 되므로 **하한이 보장된다.** 선형모델은 anchor 가 이미
피처(`tmp__y_last`)이므로 두 형태가 거의 같아 제외한다. 어느 형태를 쓸지는
**폴드 학습셋 안에서** 고른다.

### 4.4 라인업

| 모델 | 근거 |
|---|---|
| HistGBM · RandomForest · ExtraTrees | 논문 권고(RF 최강건). HistGBM 은 결측을 네이티브 처리 — 결측 39~50 % 자료에서 이점 |
| ElasticNet · BayesianRidge | 논문 : 정상상태에서는 선형으로 충분. 영천은 정상상태다 |
| kNN | 논문 : 학습시간이 중요할 때의 대안 |
| **FlowConc** | CH₄ = 유량 × 농도 분해. 유량 라벨이 2,086일로 **65 % 더 많고** 재구성 잡음이 없다 |
| **GRU** (`--with-gru`) | 논문 권고 RNN. 과거 30일 다변량 시퀀스 + 지평 h |
| SARIMAX | 논문에서 데이터셋 B 24 h OD 최고 성능. 유량 계열이 완전 관측이라 조건이 맞다 |
| Naive · SeasonalNaive | 기준선. 이걸 못 이기면 채택하지 않는다 |
| **NNLS Stack** | 비음수 스태킹. 실패 멤버를 자동으로 0 가중치 배제 |

### 4.5 검증 규약 (위반하면 결과 전체가 무효)

1. 확장창 rolling-origin. 초기 학습 **730일**, 원점 **120일** 전진.
2. 원점 O 의 학습 표본은 **t+h < O 인 쌍만**. 라벨이 O 이후를 보면 안 된다.
3. 시험 표본은 t ∈ [O, O+120) 이고 라벨은 **실측된 것만**.
4. 하이퍼파라미터·피처 선택·표적형·스태킹 가중치는 전부 **폴드 학습셋 안에서**.
   폴드 밖에서 고르면 선택편향이 성능으로 둔갑한다(이 프로젝트에서 그 크기는 27 ㎥/d 로
   측정된 바 있다).
5. 무작위 k-fold 금지.
6. 보고는 **pooled OOF R²**(요구하신 0.85 기준) + **RMSSE**(naive 대비) + 폴드별 대응 t검정.

## 6. 운전 제어 권고 (요구사항 5)

### 6.1 규칙표가 아니라 모델에 묻는다

권고는 「VFA/ALK 가 높으면 부하를 줄여라」 같은 고정 문구가 아니다. **채택된 예측 모델
자체에 반사실 질의**를 던진다.

```
조작단 x 를 현재값에서 ±k % 로 바꾼 설계행렬을 만들어 다시 예측한다
  → Δ메탄 = ŷ(x') − ŷ(x)
  → 민감도 = Δ메탄 / Δx
```

설계행렬에는 같은 원천 변수의 파생열(이동평균·시차·추세)이 여러 개 있으므로
**원천 이름이 걸린 열을 모두 함께** 흔든다. 하나만 바꾸면 모델이 모순된 입력을 받아
기울기가 왜곡된다.

### 6.2 조작단과 안전 게이트

운전원이 실제로 손댈 수 있는 것만 후보다. VFA·알칼리도·pH·NH₃-N 은 **결과이지 조작단이
아니므로** 권고 대상이 아니라 안전 게이트로만 쓴다.

| 조작단 | 열 |
|---|---|
| 소화조 투입량 | `feed_AB_tpd` |
| 기질 배합비 | `mix_foodww` / `mix_manure` / `mix_food` |
| 소화조 온도 | `dig_T_A_C` (설정치 ±1 ℃) |
| 탈수 처리량 | `dewater_tpd` |

**안전 게이트** — 하나라도 걸리면 「부하 증대」 방향 권고를 봉쇄한다.

| 게이트 | 임계 | 이유 |
|---|---|---|
| VFA/ALK | ≥ 0.40 | 산 축적. 부하를 더 넣으면 산패로 간다 |
| FAN | ≥ 300 mg/L | 암모니아 저해 구간 |
| pH | < 6.8 | 완충 붕괴 진행 |
| OLR | ≥ 4.0 kgVS/㎥·d | 지침 상한 |

### 6.3 정직성 규약

- 권고마다 **예상 ΔCH₄ 와 민감도**를 함께 낸다. 숫자 없는 권고는 내지 않는다.
- 해당 구간 모델이 naive 를 못 이기면(RMSSE ≥ 100 %) **권고를 생성하지 않고**
  「이 지평에서는 모델 근거가 없음」을 화면에 그대로 표시한다.

### 6.4 건강상태 진단은 절대임계가 아니라 상대편차로

문헌 절대임계를 그대로 경보로 쓰면 이 시설에서는 발화율이 pH **98.4 %**, OLR 86.2 %,
FAN 75.1 % 다 — 경보가 죽는다. 이 시설은 pH 7.95 · OLR 1.14 로 6년간 안정 운전한
**순치된 계**이고, 일반 기준 밖에 있는 것이 곧 이상은 아니다.

→ 경보는 **시설 자체 90일 기준선 대비 상대편차**(주의 ≥15 %, 위험 ≥25 %)로 낸다.
문헌 밴드는 경보가 아니라 「설계·문헌 대비 이 시설이 어디에 있는지」 진단으로 병기한다.

## 7. 백엔드 · 프론트엔드

업로드하신 `gemini-code-*.html`(Win32 스타일 산업용 HMI)의 **디자인을 그대로 유지**하고
하드코딩 값만 API 로 교체했다.

```
python -m src.bgp.train_bands     # 1) 구간별 평가·채택   → outputs/bands/
python -m src.bgp.serve_models    # 2) 전체 자료 재적합   → outputs/models/
python -m server.app              # 3) http://127.0.0.1:8000
```

| 엔드포인트 | 내용 |
|---|---|
| `GET /api/health` | 적재 상태·자료 범위 |
| `GET /api/bands` | 구간별 채택 모델·pooled R²·RMSSE·R² 목표 달성 여부 |
| `GET /api/overview` | 신호등 + 4개 게이지 + 경보 문구 |
| `GET /api/trend` | 실측 이력 + 구간 예측 + **95 % 경험 예측구간** |
| `GET /api/telemetry` | 계측 매트릭스(값·90일 기준선·편차·등급) |
| `GET /api/forecast` | 구간 예측 전체 |
| `GET /api/advisory` | **운전 제어 권고** + 안전 게이트 + 상태 진단 |
| `POST /api/simulate` | what-if — 조작단 변경 후 재예측 |
| `GET /api/alarms` | 경보 이력(상대편차 기준) |

설계 원칙 세 가지.

1. **서버는 학습하지 않는다.** `outputs/models/` 산출물만 읽는다.
2. **`asof` 로 원점을 옮길 수 있다.** 과거 임의 시점의 화면을 재현해
   「그날 이 화면이 무엇을 말했을 것인가」를 검증할 수 있다.
3. **예측구간은 가정한 분포가 아니라 폴드밖 잔차의 경험 분위수**다.

화면은 값을 만들어내지 않는다. 모델이 기준선을 못 이기는 구간은 붉게 표시하고
권고를 띄우지 않는다.

## 8. 한계 (숨기지 않고 적는다)

1. **V(소화조 유효용적)는 외생 상수다.** 데이터로는 식별되지 않는다(여섯 경로 전부 실패).
   OLR·HRT 는 V 가 상수이므로 투입 물량의 함수 변환일 뿐 독립 정보가 아니다.
2. **VS 물질수지는 여전히 이론 상한을 넘는다**(함축수율 ≈ 0.96 vs 이론 0.497).
   COD 기준으로 보면 Y_COD = 0.298 로 정상이므로 원인은 VS 계측(DQ-08)일 가능성이 높지만,
   가스 유량계 단위·보정 이력과 미기록 유입 유기물을 확인하기 전에는 확정할 수 없다.
3. **타깃 결측 39.4 % 가 성능의 실질 상한**이다. 이걸 푸는 것은 모델이 아니라
   연속 가스분석기다.
4. **A/B 계열은 독립 표본이 아니다**(r = 0.927). 유효표본 2배 착시를 만들지 않도록
   A 계열만 쓴다.
