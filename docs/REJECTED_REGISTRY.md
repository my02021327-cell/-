# 기각 등록부 — 업로드 자료에서 삭제한 것과 그 근거

> 요구사항 1(「내가 올린 파일 중 기각해야만 하는 내용을 삭제한다」)의 산출물.
>
> 원본은 `docs/source/` 에 **손대지 않고 보존**한다. 기각분을 삭제한 판은
> `docs/cleaned/` 에 있고, 삭제는 `scripts/clean_source_docs.py` 가 수행한다 —
> 무엇을 왜 지웠는지가 코드로 남아야 나중에 검증할 수 있기 때문이다.
> 자료·지표 층위의 기각은 문서가 아니라 코드(`src/bgp/config.py`, `src/bgp/data.py`)에서
> 자동 적용된다.
>
> **삭제 기준** — 「틀렸다고 증명된 것」과 「재현되지 않는 것」만 지운다.
> 마음에 안 드는 것, 오래된 것, 결론이 불편한 것은 지우지 않는다.

## D. 삭제하지 **않은** 것 (기각 요청이 있었어도 근거가 없어서 유지)

| 대상 | 유지 사유 |
|---|---|
| `PROMPT` §5.1 SRT 정의 (SRT = 조내 VS ÷ 유출 VS) | 정의 자체는 물리적으로 옳다. 문제는 이 자료로 **V 를 식별할 수 없다**는 것이지 정의가 틀린 게 아니다 |
| `PROMPT` §9 재현 검사 (SRT 12일·무절편에서 θ = 40.076 / 52.111 / 13.407, 학습 R² 0.293) | 회귀 테스트로서 유효하다. 파이프라인이 옛 결과를 재현하는지 확인하는 데 쓴다 |
| `EXPERT_REVIEW` 전체 | 이번 재현에서 전 수치가 확인됐다. 특히 §A2(지평)·§B1(Y_COD)·§B3(열역학 검사)은 이번 설계의 뼈대다 |
| `LESSONS_LEARNED` 전체 | 이번 작업이 A1·A4·B1·C1~C6 을 모두 재확인했다 |
| 문헌 절대 밴드(pH 6.8~7.6, OLR 1.5~4.0 등) | 경보로는 쓰지 않지만(R-07) **진단 참고**로는 유효하다. 삭제가 아니라 용도 변경 |

## E. 삭제 재현

```bash
python scripts/clean_source_docs.py     # docs/source → docs/cleaned
```

`docs/cleaning_report.json` 에 파일별 적용 내역(등록번호·삭제 줄 수·사유)이 남는다.
